# 模型费用预算与对账

调用账本记录发生了什么；费用预算决定下一次模型请求是否允许发送。两者独立：只打开账本不会限制花费。

## 开启方式

在每个会被调用的 provider（主模型、备用模型、独立视觉模型）下填写四种价格，字段与单位见 `.pico.toml.example`。价格单位为 **纳美元 / 百万词元**，1 美元 = 1,000,000,000 纳美元；显式的 0 表示已确认免费，不表示未知。项目不自动查询实时价格。

```toml
[runtime]
provider_retries = 3
fallback_providers = ""
max_iterations = 40
cost_limit_nanousd = 1000000000
```

上例的 1 美元是自选上限，不是模型价格。CLI 可用 `--cost-limit-nanousd` 覆盖；0 关闭费用准入。开启预算而缺少明确价格时拒绝启动。

预算文件为 `.pico/budgets/<session>.json`。同一主会话、Curator（历史管理器）、子任务、备用模型和视觉调用共享该账户；新会话不自动共用同一个全局月度额度。恢复已有预算时不能用配置悄悄抬高已持久化上限。

## 每次实际请求的生命周期

1. **预留**：在文件锁内检查“已结算 + 在途/未知占用 + 本次预留”不超过上限，写入唯一 attempt（尝试）记录。并发请求不能同时花掉同一余额。
2. **标记发送**：持久写入 `sending` 后才进入模型网络调用。网络等待期间不持有账户全局锁，只持有本次尝试租约。
3. **结算**：供应商返回完整用量且实际模型价格已知时，以普通输入、输出、缓存读、缓存写四类分开结算，多余预留释放。
4. **未知保留**：断流、超时或错误没有带回完整用量，就保持 `unknown` 占用，不因本地报错假定供应商未收费。实际模型价格未知或用量非法时冻结后续准入，等待对账。

预留使用当前模型配置的整个输入窗口和本次最大输出，不把本地 BPE 估算当计费上界：

`预留 = (窗口 − 本次最大输出) × max(普通输入单价, 缓存读单价, 缓存写单价) + 本次最大输出 × 输出单价`

计算按百万词元换算，使用整数纳美元，最终向上取整。这很保守：实际提示较短时，也可能需要先有足够余额覆盖整窗预留。实际账单依赖正确的价格、窗口和服务端用量；若服务端回报超出预留，记录真实费用并阻止继续透支，不把超出部分藏掉。

重试和切换备用模型各自是新的 attempt，分别预留、计量。包装顺序为“重试/备用选择 → 单次预算 → 单次账本 → HTTP”，防止把四次网络请求只记成一次，也避免重复套预算。

## 重启与人工对账

重启恢复先尝试取得该 attempt 的进程级租约，仍在执行的其他进程不会被误判为死亡：

- 残留 `reserved`：尚未进入发送状态，释放预留。
- 残留 `sending`：结果未知，转 `unknown` 并保留占用。
- 已完成 `settled`：保留真实结算结果。

REPL / TUI 使用 `/budget` 查看上限、已结算、占用、余额及冻结状态。核对供应商记录后才能手工结算：

```text
/budget reconcile 尝试ID 实际纳美元费用 对账说明
```

同一金额重复对账是幂等的，冲突金额被拒绝；正在发送的尝试不能对账。只有确认没有发生费用时才填 0，不能为解除冻结而随意清零文件。程序接入对应 `BudgetAccount.Snapshot`、`Recover`、`Reconcile`。

## 验证范围

本地测试覆盖并发额度争抢、五种模型调用接口、缓存费用、整数舍入、重试分账、真实子进程退出后的预留/发送恢复、取消与未知用量、对账幂等、活动租约冲突、损坏文件拒绝和实际费用超出预留。不运行收费 API，也不把这些测试当成供应商账单核验。
