# 上下文组装与词元预算

## 窗口从哪里来

窗口取所选 provider（模型服务）配置的 `context_window_tokens`，输出预留取 `max_output_tokens`，CLI 可以覆盖。未配置时使用项目默认值 **65,536 / 8,192**，因此默认输入上限为 **57,344 词元**；这不是自动查询到的供应商容量。切换模型时应填写该模型支持的窗口和输出上限。

```toml
[providers.deepseek]
context_window_tokens = 65536
max_output_tokens = 8192
tokenizer = "cl100k_base"
```

本地使用嵌入词表的 BPE 编码，支持 `cl100k_base`、`o200k_base`，不下载词表、不调用模型计数。它能真实计算所选编码的词元，但不等于每个供应商的分词和协议开销。额外预留的 8 个协议词元也不是供应商开销的严格上界。`--prompt-budget` 是附加字节限制，默认 0 关闭，不替代词元预算。

配置备用模型后，使用所有候选的最小窗口，并对各编码取计数最大值；任何候选的输出容量不足都拒绝启动。Worker（子任务）继承同一预算策略。

## 一轮任务如何组装

每个 Turn（用户任务轮次）开始时完整组装一次，后续 Iteration（模型与工具的一次反馈循环）增量追加，不在每次工具返回后重复调用历史筛选模型。

1. 读取工作区摘要、规则、两路复合记忆、技能和已持久化工作状态。记忆两路是宿主 `user.md` 与按当前问题召回的后端内容，不包括工作状态或聊天历史。
2. 先计算固定材料、当前请求、工具 JSON Schema（参数结构）及 8 个协议余量词元。历史额度 = max(0, 窗口 − 输出预留 − 固定材料 − 协议余量)。
3. 历史词元 **严格小于** floor(历史额度 × 0.60) 时走快速路径；等于或超过阈值进入历史管理。达到六成只是开始筛选，不表示模型窗口已经满了。
4. 原生模型请求按 `system（系统前缀）→ 历史消息 → 当前 user（用户请求）` 排列。系统前缀内部是规则与工作区、复合记忆、常驻/已激活技能、检索技能材料、工作状态。工具定义独立放在请求的 `tools` 字段，不重复拼进系统提示。
5. 对最终消息、调用参数、工具结果、模型原生推理字段与完整工具 Schema 一起复算；通过输入词元门禁和可选字节门禁后才请求模型。旧文本客户端保留文本协议兼容出口，也执行最终门禁。

例如历史额度为 20,000，则 11,999 词元快速通过，12,000 开始管理。固定材料不靠偷偷删除记忆或技能来腾空间；固定材料与保护历史仍放不下就返回预算错误，不请求主模型。

## 历史分组与保护

用户消息开启一组，后续助手消息、工具调用和工具结果归入该组，直到下一个用户消息。筛选与删除以完整组为单位，不把调用和结果拆开。

- 覆盖开头 **6 条消息**的完整组与最新一组受硬保护；不是只保存 6 条，也不是固定保护 6 组。当前请求单独保留；尾部已存同一请求时只去掉这一个重复副本。
- 未评分组初始分 **0.5**；近期 **12 条消息**覆盖的组至少 **0.75**；开头保护范围至少 **0.8**。这些是保留优先级，不是概率，也不是自动语义相似度。
- Curator（历史管理器）结合当前问题、历史、必要约束、已有决策、未解决错误与依赖，提出 0～1 的相关性分值。程序校验组号、重复项、有限数和范围；模型分数不能解除硬保护。
- 工具调用必须有对应结果，同一批次结果未补齐前不能插入新的普通消息。旧文本会话中没有调用 ID 的独立工具记录，原生转换时降为带来源标记的历史引用，不伪造调用。

## 三条选择路径

### 快速路径

历史低于六成阈值且完整输入不超限，保留全部历史；仍加载已存工作状态，仍检查完整请求预算。

### Curator 多步管理

默认最多 **12 步**，整段默认 **30 秒**合作取消时限。每步只接受一个严格 JSON 动作，输出上限为 min(2,048, 主模型输出上限)，所有辅助调用独立计量，并与主模型、Worker 共用费用预算。

可用内部动作：

| 动作 | 实际作用 |
| --- | --- |
| `budget` | 对候选组和工作状态重新组装，报告完整请求是否放得下 |
| `search` / `read` | 在全部历史组中按词查找或读取指定组；单次正文默认最多 2,000 词元 |
| `archive` / `retrieve` | 完整组先脱敏并持久归档，再降低其优先级；按本会话引用取回归档 |
| `memory` | 按查询读取记忆及已有工作状态，不执行用户工具 |
| `score` | 提交历史组相关性分值 |
| `state` | 更新最多 8 项目标、12 项未完成事项、20 项决策；每项最多 420 字符 |
| `finish` | 提交保留组；程序补回保护组并通过最终预算后接受 |

入口目录最多展示最近 64 组、每组 240 字符预览，但查找和读取可以访问更早的全部组。控制提示最多占 16,000 词元且受当前窗口限制；过大时缩小目录、去掉旧观察，不放任管理器自己无限膨胀。

归档位于 `.pico/context-archives/<会话摘要>/`，只接受本会话的内容摘要引用；写临时文件、同步并原子替换完成后才返回引用。归档和状态脱敏，读取检查摘要，单个归档上限 64 MiB。原始会话账本不因筛选或归档被删改；工作状态会在下一轮快速或慢速路径继续使用。

非法动作返回错误供下一步修正；步数耗尽、超时、模型失败或归档失败走规则回退。父任务取消直接停止。30 秒取消需要模型适配器遵守 `context.Context`，不能强杀任意不合作的 Go 协程。

### 规则回退

Curator 失败时，合并保护组、最高分约 12 条消息覆盖的完整组、最近 16 条消息覆盖的完整组。同一组可能使实际消息数超过 12 或 16。若仍超限，按低分优先、同分旧组优先删除非保护整组，直到通过完整预算或返回错误。

`--history-selector rule` 关闭辅助模型。达到管理阈值时直接使用上述规则候选集合，再执行相同的保护、闭包和最终预算检查；因此进入管理后即使仍有剩余额度，也可能筛掉非候选历史。

## 一轮执行中继续膨胀怎么办

模型返回的原生助手消息、工具调用和结果按顺序加入本轮请求。调度器的注入消息只在安全点写入会话；下一次请求增量读取，正在执行的工具不被改写。

原生请求超预算时先缩短旧工具结果正文：保留最新 **3 条工具结果**、调用 ID 与调用结构，把更早的长正文替换为明确省略标记；完整正文仍在会话账本。不会重新执行这些工具，也不会截断当前请求来伪装成功。

如果服务商仍返回窗口溢出错误，运行循环允许最多 **2 次**缩减重试检查；只有确实还能缩短正文、未输出流式片段且父任务未取消时才重试。一次缩减已移除全部可缩正文后不会原样重复发送。仍放不下则结束并返回错误。旧文本兼容路径不做原生工具正文缩减。

## 元数据与本地验证

元数据包含窗口、输出预留、输入/历史额度、六成阈值、原始/最终完整词元、计数编码、选择路径、保留组号、Curator 步数和归档引用。分段词元只作解释，不能直接相加代替最终请求复算；旧 `prompt_chars` 字段表示字节长度。计费使用供应商返回的实际用量。

本地测试覆盖 BPE 中英文计数、六成等号边界、工具 Schema 与原生字段计数、固定材料保护、多步查找/读取/归档/取回、非法动作、超时和取消、跨会话归档隔离、脱敏、工作状态跨轮复用、回退门禁和恢复闭包。不把这些离线测试写成真实模型效果成绩。
